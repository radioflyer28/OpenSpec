<decisions_made>

- Pi child sessions have assurance-only authority. The parent Pi session owns
  planning and canonical apply; this prevents the adapter from becoming a
  second writable workflow runtime.
- `planGsdChangeV1` now distinguishes a legacy writable `dispatcher` from an
  `assuranceDispatcher`. Pi supplies only the latter.
- `doGsdChangeV1` retains legacy behavior by default but Pi sets
  `allowWritablePlannerDispatch: false`.
- The single internal Pi tool delegates to existing plan/do/check/status
  implementations. It does not own a lifecycle, task queue, daemon, IPC layer,
  Git automation, worktrees, or parallel project-writing executor.
- Runtime capability evidence is live and session-local. Persisted provenance
  may include adapter/runtime/model references and capability states, but never
  secrets, prompts, private reasoning, or transient session identity.
- Read-only analyses may run concurrently only after the independent Pi
  parallelism probe passes. Project-writing execution remains sequential.

</decisions_made>

## Critical anti-patterns

| Pattern | Description | Severity | Prevention mechanism |
|---|---|---|---|
| Host-only V2 config leaking into V1 schemas | Adding `piHostAdapter` initially caused strict V1 parsing failures in run start and replay. | advisory | Keep explicit V2-only key filtering in both `runner-v2.ts` and `events.ts`; retain regression tests. |
| Pi adapter becoming a second executor/planner | A single dispatcher previously implied writable planner authority. | blocking | Keep Pi on `assuranceDispatcher` and `allowWritablePlannerDispatch: false`; tests must assert no `planner` or `executor` Pi role. |
| Persisting live runtime internals | Session identity or sensitive model/runtime context could accidentally enter generated records. | blocking | Map only the allowlisted generic provenance schema; never persist credentials, prompts, reasoning, or session IDs. |
